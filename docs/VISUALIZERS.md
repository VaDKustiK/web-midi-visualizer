# The algorithms

All styles take one normalized MIDI timeline. `t` means current playback time; `s` means note start, `d` means key-held duration. Scale factors derive from the canvas dimensions.

| Template                                              | Data → drawing                                                                                                                                                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Piano fall](../src/visualizers/pianoFall.ts)         | Pitch selects a horizontal lane. `y = keyboardY - (s - t) * speed`. Bar length is `d * speed`. Held pitches illuminate keys. The keyboard is a chromatic lane layout rather than a mechanically exact piano keyboard. |
| [Piano scroll](../src/visualizers/pianoScroll.ts)     | `x = playheadX + (s - t) * speed`; pitch selects vertical position. Duration is bar width.                                                                                                                            |
| [Constellation](../src/visualizers/constellation.ts)  | A fixed sine-based hash maps pitch to a stable star position. Concurrent notes connect to a limited number of neighbors. Stars fade after note release.                                                               |
| [Ribbons](../src/visualizers/ribbons.ts)              | Sequential notes within each track form cubic Bézier segments. Control points sit halfway between neighboring x positions. Tracks are grouped into at most five strands.                                              |
| [Note matrix](../src/visualizers/noteMatrix.ts)       | An octave-by-pitch-class grid. The grid expands to cover the file's pitch range. Velocity determines brightness; release starts a short fade.                                                                         |
| [Event terminal](../src/visualizers/eventTerminal.ts) | Show the ten most recent note-on events: timestamp, note name, velocity, track. All text is derived from MIDI.                                                                                                        |
| [Waveform](../src/visualizers/waveform.ts)            | Draw actual synthesized PCM samples against horizontal sample index. Vertical position is proportional to sample amplitude.                                                                                           |
| [Spectrum](../src/visualizers/spectrum.ts)            | Draw 48 bars sampled along a logarithmic frequency-bin axis. Height represents normalized decibel energy.                                                                                                             |
| [Spectrogram](../src/visualizers/spectrogram.ts)      | Move a history image left and append a column of logarithmic frequency energy. Color goes from deep violet to pale lavender as energy rises. History clears after seeking.                                            |
| [Resonance](../src/visualizers/resonance.ts)          | Seven polar contours. Radius combines a base circle, a slow sine displacement, and frequency-band energy. RMS energy expands all contours; active MIDI pitches place points inside.                                   |
| [Spectral flow](../src/visualizers/spectralFlow.ts)   | Scroll a waveform envelope with pitch-based purple lightness; see equations below.                                                                                                                                    |

The FFT uses a 2,048-sample Hann window, bit-reversal ordering, and radix-2 butterfly stages. This splits the waveform into frequency bins in O(N log N) work. The live browser analyser supplies equivalent waveform/spectrum data with built-in smoothing. Export uses the explicit FFT implementation.
